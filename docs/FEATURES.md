# DSH-projects 的核心功能

每项功能写三件事：它是什么、学自谁、凭什么说它能用。测试文件都在 `plugin/test/`，逐条结论见 [`TESTING.md`](TESTING.md)。

## 一句话看懂

你说一句目标。项目助理问清楚，拆成任务，交给执行者。每个任务带着它自己的上下文。做完的、要你拍板的、别人在等你回的，都回到一块看板上。你管的只有这块看板。

## 1. 交代：一句话，先问清再动手

- **是什么。** 在项目对话里说一句话。项目助理先开工不依赖答案的部分，再问你没说清的：日期到底是哪天、口径用哪个。
- **学自谁。** 项目外壳和项目说明学 Claude Projects；任务的字段和委派方式学 Multica。
- **依据。** 单测 `mira`（36 项）、`v4-native`（16 项）。端到端实测：一句话在 14 秒内拆成两个任务，并把「下周四」解释成具体日期（隔离实例，单次）。

## 2. 待你决定：一块跨项目的看板

- **是什么。** 两块，都是灰底上的白卡片。「项目进展」只放最近三天真有动静的项目，最多三个，每个一张卡：一段按项目记录重写的大白话，只写记录里有的事，不写文件路径和编号，项目一有变化就重写、最快十分钟一次；下面是等你的事（验收、拍板、没做成），最多三行，其余折成「还有 N 件等你」。没动静的项目不上看板，在左边栏里。「新消息与建议」放外面来的消息和助理自己的想法：飞书来的是飞书的标志，电脑上看到的是电脑，助理带来的是它的像素小人；等你回复的人排最前面，先显示三条。来源按卡片引用的那条记录取，不按措辞猜。卡片上没有按钮：点任务行打开任务；点消息，一整句请求写进输入框，你改完再发。
- **巡看。** 白天大约每半小时，有新动静时，个人助理把手上的任务、你自己打的字、飞书里和你有关的消息、电脑上在做的事一起过一遍，最多留两条建议。规则来自 Daimon 的几个 worker：先提你可能漏掉的，再提明确但没开始的，再提正在做的事的下一步；看板上已有的不重复。每条建议带一整句可以直接发给助理的请求：目标、材料、步骤、交付、怎么算完、哪里要先停下来问你。代码只核对出处是否真实存在、有没有重复、有没有把编号漏给你看。01:00 到 08:00 不巡看，那段时间归夜里那一轮。
- **学自谁。** 排法学 Claude 桌面端的会话侧栏，卡片学飞书的任务面板；消息列表的读法学 Gmail、Linear 和 Multica 的收件箱；状态图标学 Linear（随进度填充的圆环）。
- **依据。** 单测 `board-digest`、`inbox`、`kanban`、`followups`、`attention`。浅色、深色、窄面板都在真实浏览器里看过；点卡片只填输入框、不发送，实测过并清空。

## 3. 任务详情：做到哪一步看得见

- **是什么。** 每个任务一页：背景和你的原话、怎么算完成（执行者自己勾）、产出、读过的文件、按时间排的进展、由谁执行。
- **学自谁。** 卡片分组、字号和行高按 Codex 与 Claude 桌面端的实测数值。
- **依据。** 单测 `task-experience`（12 项）、`task-banner`。实测：执行者在三个任务上都把清单勾到 2/2。

## 4. 交付与验收：回来的是成品

- **是什么。** 网页在面板里直接渲染（沙箱里，只允许脚本），图片直接显示，文档直接预览。看过点「验收通过」，或者点「请求修改」，输入框里先填好文件名。
- **依据。** 单测 `files`、`file-maintenance`、`task-banner`。端到端实测：请求修改后 1 分 48 秒交回第 2 版（同一次实测）。

## 5. 拍板：关键的事你来定

- **是什么。** 执行者需要你决定时给一张选项卡片，推荐项标出来。你选了，任务回到原来的状态接着做；已经交付的任务不会被打回进行中。
- **依据。** 单测 `mira`、`live-reply`。实测：选了非推荐项，任务继续。

## 6. 执行者可换：DeepSeek Harness、Claude Code、Codex

- **是什么。** 每个任务可以单独换执行者和模型。各家保留自己的原生会话，换回来接着同一个会话。可以「我来接手」再「交还」，交接时系统数出这期间多了几条消息、几轮执行，告诉接手的一方。换了以后，在任务原来的对话里输入的话会转给新的执行者，旧对话不再自己动手。
- **依据。** 单测 `task-runner`（9 项）、`runtime-takeover`、`external-runtime`、`task-model`。2026-11-16 在试用项目里实测：切到 Claude Code 后在旧对话里输入，话进了任务、Claude Code 回了、旧对话步数 14 → 14 没有再跑。
- **还没验到的。** Codex 用它自己的模型跑完一个任务。试的两台机器上，一台登录失效，一台的模型密钥放在 DSH-projects 不传给执行者的环境变量里。接一个不是 OpenAI 的模型实跑过一次：启动、交接、收尾是通的，但那个模型看不到 DSH-projects 的工具，是绕开正常通道做完的，不算通过。细节见测试报告。
- **要知道的。** Claude Code 和 Codex 当执行者时不弹权限确认，也没有沙箱：你这个系统用户能读写的它都能读写。

## 7. 个人助理与记忆：记得你说过的话，有出处

- **是什么。** 一个助理看着所有项目。「关于你」只记你亲口说的话，每条带原话，能改、能撤销；「工作」记忆每条带依据。对话空闲后它会自己把你说过的要紧话记下来，晚上再整理一遍。
- **依据。** 单测 `auto-memory`（19 项）、`hub-about`（10 项）、`memory-evidence`、`personal`、`personal-index`。代码会核对：引用的原话必须真的在那条消息里。

## 8. 只读接入：飞书和电脑

- **是什么。** 飞书消息实时读取（只读），有人等你回会进「等你」。电脑上的文件可以让助理只读：指定文件夹，或全部文件（去掉系统和隐藏目录）。都能随时关。
- **依据。** 单测 `feishu-live`、`feishu-chat`、`mac-files`（18 项）、`observations`、`observation-client`（20 项）、`source-retention`（15 项）。

## 9. 夜里想一轮

- **是什么。** 夜里电脑空闲时，助理把这一天过一遍，至少想三轮，留下最多三件事：一件可以做、一件可以看、一句想说的。每件必须指得出出处。已经定下来的事不会再提，也不评价你的作息。早上它们出现在「等你」里，另有一页日记。
- **依据。** 单测 `dream`（7 项）、`skills`。隔离实例里用真模型跑过三晚的材料，没有再提已经拍板的事。代码核对：出处编号必须是材料里给过的，数字必须来自材料。

## 10. 时间线、自动任务、助理与模型

- **时间线。** 今天和昨天按钟点排：电脑上的活动和项目里的事件在同一条线上。学 ChatGPT 的 Computer History。单测 `computer-history`。
- **自动任务。** 项目里定时跑的任务，用 DeepSeek Harness 的调度。单测 `automations`（11 项）。
- **助理与模型。** 每个助理一页：什么时候醒、每轮读到什么、用什么模型；项目的模型策略可以用一句话写。单测 `agent-profile`、`members`。

## 底下的三条规矩

1. **一条日志就是事实。** 所有状态都是事件日志里的记录，看板、任务详情、记忆都从它算出来。日志最后一行写坏了也能接着用（单测 `store-torn-line`）。
2. **唤醒只带数，不带正文。** agent 被叫醒时只知道「哪里有几条未读」，正文自己去收件箱读，回合结束才确认。唤醒丢了，消息不丢。这是从 Raft 学的。
3. **代码只校验，理解交给模型。** 代码只查机械的事：引用的东西在不在、数字有没有出处。意思和措辞交给模型。

## 边界

- 不替你拍板，不替你验收，不以你的名义发消息。
- 飞书只读；电脑文件只读，只读你允许的。
- 只能跑在 DeepSeek Harness 里。
